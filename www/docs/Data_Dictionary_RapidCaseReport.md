# RapidCaseReport | Reports Data Dictionary

**Applies to:** RapidCaseReport v2.x. **Revision:** 2026-11-23.

The application stores confirmed case reports in a local SQLite table called `reports` by default. `R/report_database.R` creates or extends this schema. It exports only records saved in the current Shiny session through **Download Current Session CSV**; this is not a historical database export.

| Field | Stored type | Source / interpretation |
|---|---|---|
| `id_code` | TEXT primary key | UUID from `generate_id()`. |
| `consultation_date` | TEXT | Date selected in the form, typically `YYYY-MM-DD`. |
| `sex` | TEXT | `Male`, `Female`, `Other`, or `Prefer not to say`. |
| `birth_date` | TEXT | Date selected in the form. |
| `country` | TEXT | Selected country key. |
| `level1` | TEXT | First geographic selection, generally its display name. |
| `level2` | TEXT | Second geographic selection, generally its display name. |
| `level3` | TEXT | Finest selected geographic area ID from the map. |
| `symptom_onset_date` | TEXT | Date selected as symptom onset. |
| `symptom_description` | TEXT | Free-text symptoms. |
| `suspected_diagnosis` | TEXT | Free-text suspected diagnosis. |
| `confirmation_time` | TEXT | Submission timestamp generated by `format_new_entry()`. |
| `submitted_at` | TEXT | Submission timestamp used in session preview/export. |
| `email` | TEXT | Reporter email from form. |
| `institution` | TEXT | Reporter institution from form. |

All fields above exist in a newly initialized table. The validator explicitly requires sex, email, institution, symptoms, diagnosis, country and a final area; it checks the email pattern and that birth date does not follow consultation date. Some date inputs have UI-level future-date limits, but the validator does **not** enforce every relationship between symptom onset, birth and consultation dates. Do not infer complete medical-data validation from a populated field.

**Confidentiality:** source records and downloaded current-session CSVs may contain sensitive case information. This implementation has no built-in user accounts, history download or record-edit screen; those operational controls must be provided externally.

See [Developer Guide](DEVELOPER_GUIDE.md), [Institutional Setup Guide](INSTITUTIONAL_SETUP_GUIDE.md) and [User Guide](USER_GUIDE.md).

## Terminology and subsequent analysis

`symptom_description` and `suspected_diagnosis` are free-text fields. Differences in terminology, spelling or abbreviation may prevent direct grouping of equivalent clinical concepts. Institutions should consider approved terms or a documented standardisation procedure before using exported records for analysis in API-POP.
